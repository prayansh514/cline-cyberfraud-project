# 🛡️ Project ScamGuard: Automated Cyber-Fraud Shield

## 📖 Project Overview
India's rapid adoption of digital payments has led to a massive increase in cyber fraud, disproportionately affecting vulnerable populations like the elderly who struggle to verify malicious links or spoofed messages. 

**ScamGuard** is a React-based Chrome Extension that acts as an automated, privacy-first cybersecurity expert. It sits silently on top of platforms like WhatsApp Web. Instead of requiring users to manually upload screenshots, it automatically detects high-risk messages, sanitizes them for privacy, and uses a stateless AI agent to evaluate the threat level in real-time. If a message is deemed malicious, the extension visually quarantines the message bubble and explains the scam to the user.

This project directly targets a critical, real-world Indian problem[cite: 11] and is designed to be fully completed within an 8-hour hackathon sprint.

## 💻 Tech Stack & Architecture

This project utilizes a split-stack architecture, separating the browser extension frontend from the AI-powered backend. We are using standard JavaScript across the entire stack.

### Frontend: React Chrome Extension
*   **Framework:** React 18 with JavaScript.
*   **Build Tool:** Vite.
*   **Extension Plugin:** `@crxjs/vite-plugin` (allows for hot-reloading of the Chrome extension during development).
*   **Styling:** Tailwind CSS (for injecting warning banners and popup UI).
*   **Core Logic:** JavaScript `MutationObserver` to monitor the DOM for new messages and local Regex filtering to detect URLs or high-risk keywords before sending any data.

### Backend: Node.js & Cline SDK
*   **Server:** Node.js with Express and CORS.
*   **AI Agent Harness:** `@cline/sdk`. We are targeting the hackathon bonus points by using the SDK directly inside the product[cite: 11].
*   **Execution Loop:** `@cline/agents`. This specific package provides a stateless agent loop that is perfect for one-shot tasks and lightweight in-process use without requiring complex session storage.
*   **Speed Advantage:** The `@cline/agents` quickstart requires roughly only 15 lines of code to send a prompt and stream a response, making it highly optimized for an 8-hour hackathon.

## ⚙️ The Execution Workflow

1.  **Local DOM Monitoring:** The React extension runs a background content script on WhatsApp Web, watching for incoming message bubbles.
2.  **Privacy-First Pre-Filtering:** The extension runs a local regex check. If the message contains no links, financial keywords, or unknown numbers, it is ignored.
3.  **Data Anonymization:** If flagged, the extension masks sensitive entities (e.g., replacing real names with `[NAME]`) before making an HTTP request to the backend.
4.  **Stateless AI Analysis:** The Node.js server receives the text and passes it to the `@cline/agents` runtime. The agent acts as a forensic analyst, returning a verdict (Safe, Suspicious, or Malicious) along with a brief explanation.
5.  **Visual Intervention:** The React extension receives the verdict. If "Malicious", it injects a red CSS outline around the specific message bubble in the browser and disables any clickable links to protect the user.

## 🧪 Development & Testing Process

To ensure a flawless live demo and rapid iteration during the hackathon, we will use a continuous Hot Module Replacement (HMR) testing loop.

### 1. Environment Setup
*   **Dual Terminals:** We will run two simultaneous development servers in VS Code.
*   **Backend:** `npm run dev` in the `/server` directory (runs Express via `nodemon` for auto-restarts).
*   **Frontend:** `npm run dev` in the `/client` directory (runs Vite).

### 2. Chrome Extension Injection
*   Navigate to `chrome://extensions/` in Google Chrome.
*   Enable **Developer mode**.
*   Click **Load unpacked** and select the `dist` folder generated by Vite in the `/client` directory.

### 3. The Continuous Testing Loop
*   **Auto-Reloading UI:** Because we are using `@crxjs/vite-plugin`, any changes saved to the React components or content scripts in VS Code will instantly hot-reload inside the browser. There is no need to manually refresh the extension page.
*   **Live DOM Testing:** We will keep a mock WhatsApp Web HTML page (or actual WhatsApp Web) open in Chrome. As we adjust the Tailwind CSS injection logic in our code, we will see the red warning boxes update live on the target messages.
*   **Backend Validation:** We will monitor the Node.js terminal logs to verify that the `@cline/agents` package is successfully receiving the anonymized text and returning the correct JSON structure.
